# 01 — 연차 쓰는 날 강조와 풋노트 (연휴 조합 추천 화면)

## Outcome

사용자는 지금의 "연휴 조합 추천" 화면에서 연차를 써야 하는 날짜를 칩으로 한눈에 알아보고, 처음 화면부터 2027년만 지원한다는 제약을 알 수 있다. 계산 결과와 안내 조건은 그대로다.

- 결과의 "연차 쓰는 날" 날짜가 날짜마다 연한 배경의 작은 칩이며 굵은 글씨와 `chart-4` 글자색으로 보인다. 칩 사이의 쉼표는 화면에 보이지 않고 화면 낭독기에는 날짜가 쉼표로 구분되어 읽힌다. 넓은 화면의 표와 좁은 화면의 카드가 같은 방식이다.
- 화면 아래 풋노트에 2027년 제약 설명이 처음 화면부터 항상 보이고, 결과에 연휴가 있을 때만 강조 설명("강조 표시된 날짜는 연차를 써야 하는 날입니다.")이 더해진다.

## Blockers

None.

## Acceptance criteria

- [x] 처음 화면에서 2027년 제약 설명이 보이고 강조 설명은 보이지 않는다.
- [x] 연차 2일, 기본 기간에서 1위 조합의 9/13·9/17이 칩으로 강조되어 보인다.
- [x] 강조는 표(넓은 화면)와 카드(좁은 화면, 375px) 양쪽에서 같은 방식으로 보인다.
- [x] 결과에 연휴가 있으면 풋노트에 강조 설명과 2027년 제약 설명이 모두 보인다.
- [x] 연차 1일, 1/4~1/4처럼 조합이 없을 때는 2027년 제약 설명만 보이고 강조 설명은 없다.
- [x] 연차 0일처럼 입력 오류일 때도 2027년 제약 설명이 보이고, 기존 오류 안내는 그대로다.
- [x] 강조 칩의 글자와 배경의 대비가 실제 화면에서 4.5:1 이상이다.
- [x] 기존 테스트의 계산 결과와 안내는 모두 그대로 통과한다. 날짜를 칩으로 감싸도 칸을 읽는 글자(화면 낭독기와 복사 결과)는 같다.
- [x] 칩 사이의 쉼표가 표와 카드 양쪽에서 화면에 보이지 않고, 읽는 글자에는 남는다.

## Constraints

- [ui-composition](../../../decisions/ui-composition.md): 칩, 풋노트, 표와 카드를 shadcn 구성과 token으로 만들고 좁은 화면(768px 미만)에서 표를 카드로 쌓는 규칙을 정한다. 이 task는 그 규칙 안에서 강조 색상을 spec의 가정대로 쓴다.
- 색과 문구의 상세는 spec의 "표시 요구사항"과 "가정"이 정한다. 이 파일에 복사하지 않는다.

## Verification

- 화면 테스트: 처음 화면의 풋노트, 연차 2일 기본 기간의 강조 날짜, 조합 없음, 입력 오류 각각에서 보이는 풋노트 문구.
- 기존 화면 테스트와 계산 테스트 전체가 그대로 통과한다.
- 브라우저에서 375px(카드)와 넓은 화면(표)을 직접 열어 같은 날짜가 칩으로 강조되는지 확인한다.
- 칩에 실제로 칠해진 글자색과 배경색으로 대비를 계산해 4.5:1 이상인지 확인한다.
- 타입체크와 빌드가 통과한다.

## Execution

- Verification: 화면 테스트 74개 통과(기존 66개 + 새 8개), 타입체크 오류 없음, 빌드 성공, e2e 1개 통과. 브라우저로 폭 375px(카드)와 1280px(표)에서 연차 2일 기본 기간의 9/13·9/17이 칩으로 보이고, 칩 글자와 배경의 대비가 실제 칠해진 색으로 4.65:1(카드 흰 배경 기준), 연차 30일 카드에서 날짜 30개가 가려지지 않음, 입력 오류(연차 0일)에서 오류 안내와 제약 설명만 보이고 칩이 없음을 확인했다.
- Verification (쉼표 정리 후): 화면 테스트 76개 통과(기존 66개 + Task 1 새 10개), 폭 375px(카드)와 1280px(표) 브라우저에서 쉼표가 화면에 보이지 않고(숨긴 쉼표 1x1 픽셀로 잘림) 칸을 읽는 글자는 "9/13(월), 9/17(금)" 그대로임을 확인했다. 연차 30일 카드는 칩 30개와 숨긴 쉼표 29개, 가로로 넘치지 않음.
- Blocker: —
- Revision: 날짜를 칩으로 감싸자 기존 카드 테스트의 `getByText("9/13(월), 9/17(금)")` 조회가 한 덩어리 글자를 찾지 못했다. 기대값은 그대로 두고 칸에 보이는 글자를 읽는 방식(`toHaveTextContent`)으로만 바꿨다. spec의 "남은 위험"에 적힌 영향이다.
